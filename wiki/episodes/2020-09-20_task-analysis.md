# Task Analysis: Support Users in Achieving Their Goals

## Summary

Task analysis is the systematic practice of learning how users work (tasks they perform) to achieve their goals. Emerged from instructional design and human factors, task analysis is crucial because designs solving wrong problems fail regardless of UI quality. A task is any observable activity with a start and end point, distinct from goals (what users want to accomplish) and different from job analysis (employee roles over time) or workflow analysis (work across multiple people). Task analysis comprises two stages: gathering information on goals and tasks through observation and interviews, then analyzing tasks to understand number, sequence, hierarchy, complexity, and producing diagrams.

## Key Takeaways

- **Goal vs. task distinction** — Goals are what users want to accomplish (e.g., set up retirement fund). Tasks are activities users perform to achieve goals (e.g., search for deals, consult advisor, fill application). Multiple tasks serve single goals.
- **Stage 1: Gather information** — Use combination of methods: contextual inquiry (visit users onsite, conduct semistructured interviews, watch users work, ask followup questions), critical incident technique interviews (users recall incidents; interviewer asks detailed followup questions), record keeping or diary studies (users document tasks over time), activity sampling (watch or record users to document tasks, duration, frequency), simulations (analyst walks through user steps).
- **Stage 2: Analyze tasks** — Structure observations by attributes (order, hierarchy, frequency, cognitive demands). Create task-analysis diagram (most common: hierarchical task analysis or HTA). Start with goal and scenario, highlight major tasks (operations), break down into subtasks. Capture plans (which steps occur in which order, when steps are optional).
- **HTA depth and attributes** — Number of subtask levels depends on complexity and desired granularity. Analyze tasks for overall number, frequency, cognitive complexity (mental processes required), physical requirements, and time taken. Note areas for design improvement.
- **Design application** — Understanding tasks, goals, sequences, and complexity helps designers create efficient, intuitive, easy-to-use products. HTA serves as communication tool and starting point for further analysis.

## Quotes

> Task analysis refers to the broad practice of learning about how users work (i.e., the tasks they perform) to achieve their goals.

> a design that solves the wrong problem (i.e., doesn't support users' tasks) will fail, no matter how good its UI.

> Not all users accomplish goals in the same way. For example, a novice user might perform more tasks than an expert user — the latter might skip certain steps.

## Concepts

- [[User Research]] — Task analysis is a systematic research method that connects user goals to the tasks performed to achieve them, revealing optimal process flow and opportunities to streamline, simplify, or improve task completion, providing the foundation for design decisions that actually support user work.
- [[Task Design]] — Understanding task sequences, subtasks, cognitive demands, and physical requirements helps designers create workflows and interfaces that support efficient and effective user performance.
