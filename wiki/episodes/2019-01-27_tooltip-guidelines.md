# Tooltip Guidelines

## Summary

Tooltips are brief, informative messages that appear when a user hovers over an element in a graphical user interface. This article provides best practices for designing tooltips effectively, distinguishing them from similar UI patterns like popup tips and discussing their appropriate use cases. The key principle is that tooltips should provide supplementary information for elements, not essential information required for task completion.

## Key Takeaways

- **Don't use tooltips for vital information** — Tooltips should provide additional explanation for form fields or reasoning for unusual requests, but instructions or directly actionable information should always be visible on screen, not hidden in tooltips.
- **Keep tooltip content brief and helpful** — Tooltips should contain relevant microcontent that adds value to users; redundant or obvious text should be avoided to prevent wasting user time.
- **Support both mouse and keyboard hover** — Tooltips must be accessible via both mouse hover and keyboard focus to ensure users who rely on keyboards can access the same information.
- **Use arrows to clarify association** — When multiple elements are near each other, tooltip arrows help users clearly identify which element the tooltip is associated with.
- **Maintain consistency** — Tooltips should be consistently applied throughout a site; either provide tooltips for all similar elements or use popup tips for inconsistent labeling.
- **Provide tooltips for unlabeled icons** — Most icons are ambiguous and require text labels; at minimum, icons should have descriptive tooltips to help users understand their purpose.

## Quotes

> A tooltip is a brief, informative message that appears when a user interacts with an element in a graphical user interface (GUI). Tooltips are usually initiated in one of two ways: through a mouse-hover gesture or through a keyboard-hover gesture.

> Thus, tooltips are highly contextual and specific and don't explain the bigger picture or entire task flow.

> The more we strive for extreme minimalism, the more tooltips we'll need, and the more work for our users.
