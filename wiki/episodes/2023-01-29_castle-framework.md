# CASTLE Framework for Productivity/Workplace Applications

## Summary

The CASTLE framework is a UX measurement framework designed for productivity and workplace applications where users cannot choose whether to use the product, addressing limitations of Google’s HEART framework for these contexts. CASTLE stands for Cognitive Load, Advanced Feature Usage, Satisfaction, Task Efficiency, Learnability, and Errors. Like HEART, CASTLE breaks each dimension into goals, behavioral signals, and quantifiable measures. The framework guides teams in identifying meaningful metrics rather than prescribing specific measurements.

## Key Takeaways

- **CASTLE complements HEART for workplace software** — HEART’s dimensions (engagement, adoption, retention) are less applicable to mandatory-use products; CASTLE provides constructs better aligned to workplace UX priorities.
- **Cognitive Load dimension** — Mental effort required for task completion, including working-memory burden and workflow resumption; measured through surveys (NASA-TLX) or usability-inspection methods, not easily observable through analytics.
- **Advanced Feature Usage** — Voluntary adoption rates for optional advanced features (accelerators, customization); indicates discoverability and clarity; helps prioritize feature roadmaps rather than driving intrusive education.
- **Satisfaction** — User feelings about using the product; measured through surveys, post-task questionnaires, and indirect signals like "rage clicks" rather than analytics alone.
- **Task Efficiency** — Speed and step-count to complete key workflows; best measured through controlled quantitative usability testing rather than unreliable analytics (external interruptions skew results).
- **Learnability** — Effort, time, and resources for new users to become productive; measured through longitudinal usability testing, log analysis of task-performance improvements, or cognitive walkthroughs.
- **Errors** — Both data-quality issues (entry slips, mistakes) and system-error messages; measured through analytics instrumentation and analysis of repetitive error-loop behaviors.

## Quotes

> Importantly, this metric is not intended to foster user-education initiatives such as intrusive push revelations and onboarding tutorials (which often fail to get usage rates up) but, instead, is meant to help the team evaluate the discoverability, clarity, or usefulness of these features, and to help prioritize future feature roadmaps.

> metrics don’t provide information as to why that is happening, nor do they tell us how to improve the current state.

## Concepts

- [[UX Metrics]] — CASTLE provides a measurement framework for workplace applications where each dimension breaks into goals, signals, and measures to guide metric selection and tracking; effective measurement requires combining quantitative metrics (for tracking progress) with qualitative research (for understanding why), since metrics alone tell what changed, not how to improve.
- [[Analytics]] — The framework emphasizes choosing measurement approaches (analytics, surveys, testing, inspection) appropriate to each dimension; not all dimensions are best measured through analytics.
- [[Workplace Software]] — Workplace and productivity applications have distinct UX priorities (cognitive load, learnability, error prevention) that differ from consumer products; CASTLE addresses these specific needs.
