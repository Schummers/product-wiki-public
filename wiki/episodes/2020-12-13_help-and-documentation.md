# Help and Documentation (Usability Heuristic #10)

## Summary

This article explores the tenth usability heuristic: systems should provide help and documentation when necessary. The article distinguishes between proactive help (provided before users encounter problems, like onboarding tutorials and contextual tips) and reactive help (provided when users seek assistance, like FAQs and documentation). It covers two types of proactive help (push and pull revelations), best practices for each, and guidance for reactive help including how to make documentation scannable and searchable.

## Key Takeaways

- **Proactive help prevents problems** — Tutorials, instructional overlays, and contextual tips help new users, novices, and users encountering redesigned interfaces learn the system, but must be kept short and contextually relevant.
- **Push vs pull revelations** — Push revelations provide unsolicited help to all users (like onboarding tutorials) but are often ignored; pull revelations provide contextual tips relevant to the user's current task and are more effective.
- **Favor pull over push** — Make help accessible but don't force users into it; use pull revelations for timely help and push revelations only for essential information, always allowing easy dismissal.
- **Reactive help must be comprehensive** — Documentation and FAQs should provide detailed, specific information, not just obvious details, because users consulting them have actual problems to solve.
- **Optimize documentation design** — Support scanning with clear hierarchy, chunk content, use highlighted keywords and lists, provide both text and video, optimize search functionality, group help into categories, and highlight top content.

## Quotes

> Even though it is better if the system can be used without documentation, it may be necessary to provide help and documentation. Any such information should be easy to search, focused on the user's task, list concrete steps to be carried out, and not be too large.

> **The goal of proactive help is to familiarize users with an interface.**

> They need help with something and likely want detailed instructions. Documentation like this should not solely provide high-level overviews, though that content is warranted at the top of the page.

## Concepts

- [[Help Systems]] — providing both proactive help (tutorials, tooltips, contextual hints) and reactive help (documentation, FAQs, training) to support users at different points in their experience.
- [[Onboarding]] — proactive help for new users at first launch or first encounter with a redesigned interface, including tutorials and instructional overlays that help users learn the system initially.
- [[Documentation]] — reactive help including FAQs, technical manuals, training modules, and video tutorials that users consult when they encounter problems or want to become expert users.
