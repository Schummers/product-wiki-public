# 10 Design Guidelines for Reporting Errors in Forms

## Summary

This article provides comprehensive guidelines for designing effective error flows in forms, enabling users to easily identify, understand, and fix their mistakes. The guidelines focus on reducing interaction costs and cognitive load through clear error messages, strategic placement, appropriate visual design, and progressive validation strategies. Good error design ensures users can complete their tasks despite mistakes.

## Key Takeaways

- **Use inline validation** — Errors should appear as soon as users finish filling a field, allowing them to fix mistakes immediately without searching for problematic fields.
- **Show success indicators for complex fields** — For fields with specific requirements like passwords, provide real-time validation feedback as users type to help them meet guidelines without trial and error.
- **Keep error messages next to fields** — Error messages should appear adjacent to the problematic field to minimize working-memory load and help users understand which field needs correction.
- **Use color and icons for clear differentiation** — Red coloring, background highlights, and icons help users quickly scan and identify errors, especially important for users with color blindness.
- **Avoid tooltips for error reporting** — Tooltips hide critical error information behind hover states or focus, making errors hard to notice and requiring extra effort to access the message.
- **Provide extra help for repeated errors** — When users encounter the same error three or more times, this signals a deeper usability problem that requires design review and clearer messaging.

## Quotes

> An error flow should allow users to easily fix their mistakes and proceed with their tasks.

> When users encounter the same error repeatedly (3 or more times in a single form-filling attempt), it indicates a deeper issue in the user interface — unclear error messages, a mismatch between the design and users' needs, or overly complex requirements in the form.

> Keeping error messages next to the fields in error minimizes working-memory load: users can see the error message while fixing the error instead of having to remember it.
