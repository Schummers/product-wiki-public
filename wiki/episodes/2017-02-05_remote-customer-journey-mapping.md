# Remote Customer Journey Mapping

## Summary

Journey mapping with distributed teams faces distinct challenges: lack of buy-in for the process, lack of belief in outcomes, and difficulty iterating on static documents. Digital tools at three levels help overcome these barriers. Level 1 tools (visualization only) serve individuals; Level 2 tools (real-time collaboration) support distributed teams; Level 3 tools (integration and consolidation) handle multiple data sources and ongoing management. Selecting the right tool depends on team resources, available data, and budget.

## Key Takeaways

- **Distributed teams face amplified journey-mapping challenges** — geographic dispersion exacerbates lack of buy-in, outcome skepticism, and iteration difficulty compared to co-located teams.
- **Level 1 tools support visualization and sharing** — Canvanizer, OmniGraffle, Gliffy, and Lucidchart provide blank canvases for digital maps; inexpensive but lack real-time collaboration.
- **Level 2 tools enable synchronous collaboration** — Mural, Miro, Smaply, and UXPressia allow multiple contributors to work simultaneously, mirroring in-person workshop benefits for remote teams.
- **Level 3 tools integrate external data** — Touchpoint Dashboard, IBM Journey Designer, and CFN Insight allow personas, metrics, and voice-of-customer data integration; expensive but robust for enterprise needs.
- **Tool selection depends on team size** — UX teams-of-one need Level 1; larger teams benefit from Level 2 collaboration features.
- **Data integration needs drive tool choice** — organizations managing multiple data sources and ongoing CX programs justify Level 3 investment.
- **Right tools reduce journey-mapping failure modes** — digital formats solve document staleness, enable updates, and support distributed participation better than static physical artifacts.

## Quotes

> Journey mapping fails when there is lack of buy-in, when the findings are not socialized, and when teams view the outputs as "final."

> Because the journey map itself is oftentimes a physical, static document that can be difficult to update and build upon, many people misunderstand the result of a journey-mapping endeavor to be "final."

> While no tool will ever completely overcome all the impediments to journey-mapping success outlined in the previous section, the right tools can at least make this process less arduous and increase the chances of a favorable outcome, for both distributed teams and those in the same building.
