# Opening Links in New Browser Windows and Tabs

## Summary

Since 1999, web-usability guidance recommends refraining from opening new browser windows or tabs for several reasons: increased clutter, disorientation, difficulty for less-technical users (especially mobile), prevention of Back button use, and inaccessibility for blind/low-vision users. However, one legitimate reason exists: when users will need to refer to content in one window while completing a task in another window. Recent research identifies specific task types where new windows are well-received and others where users dislike them, suggesting context, device, and task matter more than link type.

## Key Takeaways

- **General rule: Same window** — For most situations, open links in the same browser tab or window. Resist temptation to open new tabs based on link type or content format assumptions.
- **When new windows work** — Users appreciate new windows/tabs for: (a) comparing content across windows/tabs; (b) combining information from multiple windows/tabs to complete tasks; (c) keeping track of items using page parking; (d) using original tab as launching-off point to others while returning to it later.
- **When users dislike new windows** — Users did NOT appreciate new windows/tabs for: quick inspection of a page followed by resuming activity in original tab, multistep workflows where new steps appear in different windows (users prefer Back button), or when many tabs already open (increased information-management burden).
- **Context matters most** — User reactions depend on context (casual tasks vs. high-pressure scenarios), device (mobile users struggle most), and task type. File format or link type alone should not determine new-window behavior.
- **PDF handling** — Best practice uses HTML gateway pages summarizing PDFs with option to download. If PDFs must open in browser, open in new tab on desktop (users often go back and forth between PDF and original page). On mobile, open in same tab for Back button access.
- **Signaling important** — When opening new windows is necessary, use contextual messaging and icons to alert users before they click, setting expectations.

## Quotes

> The reason we can't just generalize when to open a link in a new browser tab (or window) versus keep users in the same browser tab is because our user's needs, expectations, and reactions aren't triggered by a file format or link type (internal or external).

> By gratuitously adding an extra window or tab, you are increasing users' information-management burden.

> For the most part,alwaysopen links in the same browser tab or window. However, if you hypothesize that opening a new tab or window may help users in their task, don't base this decision on the type of link or content alone. Rely on observational research methods, like usability testing, contextual inquiry, and field studies to help you make the right call.

## Concepts

- [[Navigation Design]] — Opening new windows or tabs disrupts navigation patterns, particularly the Back button affordance. Navigation decisions must be based on task type and context, not link type alone.
- [[Usability Guidelines]] — Long-standing guideline against opening new windows remains valid, with exception for tasks requiring reference to multiple pieces of content simultaneously. User research should confirm new-window benefit before implementation.
- [[Link Behavior]] — Link behavior expectations depend on task context (comparing, combining, tracking, launching-off), device capabilities (mobile users struggle with new windows), and existing information load (adding tabs to already-cluttered experiences frustrates users).
