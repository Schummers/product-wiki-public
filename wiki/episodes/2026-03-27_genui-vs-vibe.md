# GenUI vs. Vibe Coding: Who's Designing?

## Summary

Generative UI (where the AI system decides to produce an interactive element) differs fundamentally from vibe coding (where the user asks the system to build something). This distinction matters because it determines who makes design decisions and what accountability falls on the system. In genUI, the AI is accountable for design judgment; in vibe coding, the AI executes the user's vision. Vibe coding can range from vague specifications (giving AI much design latitude) to highly detailed specifications (constraining AI to execution). Most people cannot envision and articulate interfaces; genUI serves them. Vibe coding's "build-your-own-everything" narrative underestimates how hard it is for most people to specify what they want built.

## Key Takeaways

- **Who initiates design** — GenUI: the AI decides to generate UI. Vibe coding: the user asks for UI. This distinction determines accountability.
- **Specification spectrum** — Vibe coding ranges from vague ("build a trip planner") to highly detailed, which shifts the AI's role from design to execution.
- **Design burden differs** — Vibe coding fails when execution is poor; genUI fails when design judgment is poor. Different failure modes need different evaluation.
- **Most people can't vibe code well** — The narrative that everyone will build custom software assumes users can think in apps and interaction patterns; most people cannot.
- **GenUI's broader reach** — Vibe coding empowers people who can articulate what they want; genUI benefits everyone, including those who wouldn't think to ask for an interface.
- **Invisible AI future** — Future genUI will work behind the scenes, customizing existing interfaces without the visual sparkle; evaluation will require user research, not just rendering quality.

## Quotes

> "Vibe coding assumes a user who can think in terms of apps, dashboards, and interaction patterns. That's a meaningful prerequisite, and not one most people meet."

> GenUI serves the rest. "Help me plan my trip" is a prompt anyone might type. If the system responds by generating a custom itinerary tool rather than a paragraph of text, someone who would never think to vibe code a trip planner still gets the benefit of an interface designed for their situation.
