# Feature Checklists Are Not Enough: How to Avoid Making Bad Software

## Summary

Software can implement all required features correctly yet still provide a poor experience if features and information are not presented at the point of need in the logical sequence users follow. Task flow and timing matter as much as feature completeness. Interrupt-heavy designs force users to constantly stop working toward their goal and search for the next needed function or information. Good software must present information and features in the sequence and location where users actually need them. Task analysis and jobs-to-be-done analysis uncover the exact sequence of actions users take, enabling designers to map screens to user needs. Without this analysis, workflow problems become embedded in the system and remain chronic issues difficult to fix later because they may require refactoring existing functionality.

## Key Takeaways

- **When Equals What** — Including all necessary features is insufficient; timing and sequence are equally important; features and information must appear at the point of need when users require them.
- **Point-of-Need Placement** — Present information and controls where users need them in their workflow; basic information essential to primary tasks should be highly visible, not hidden behind clicks.
- **Reduce Interruptions** — Interrupt-heavy designs that require users to hunt for functions create constant workflow disruption instead of supporting progress toward goals.
- **Task Flow Awareness** — Different users may prefer different task sequences; design should support common and important sequences while maintaining flexibility where possible.
- **Feature Accessibility Problem** — Warning indicators and alerts should be actionable at their location; forcing users to navigate to separate screens to take action breaks workflow continuity.
- **Task Analysis Foundation** — Detailed understanding of exact user steps and sequences is essential before structuring application screens; use task analysis or jobs-to-be-done methods.
- **Persistent Problems** — Workflow issues embedded during design are chronic problems that persist because fixing requires refactoring existing functionality rather than adding new features.

## Quotes

> For interactive software for complex tasks, including all the necessary information and features is not good enough; it's also essential to pay attention to the sequence of steps and organization of the available features.

> This design imposes a high interaction cost on users just to see basic information essential to the primary task of reviewing the report.

> Because it's so difficult to correct such problems, it's much better to avoid creating them in the first place, by making sure you have a detailed understanding of exactly what users need at each step of a task, before you begin structuring your software screens.

## Concepts

- [[Task Flow]] — The sequence of actions users take to accomplish goals; essential to understand before designing screens.
- [[Software Design]] — Creating interfaces that support user workflows requires attention to task sequences and point-of-need placement, not just feature completeness.
- [[User Workflow]] — The natural path and sequence users follow; design must remove interruptions and support rather than impede workflow.
- [[Information Architecture]] — How information is organized affects whether users can find what they need at the point when they need it.
- [[Interaction Cost]] — Hidden information behind clicks increases interaction cost; essential information for primary tasks should be visible.
