# UI Copy: UX Guidelines for Command Names and Keyboard Shortcuts

## Summary

This article provides guidelines for crafting effective user-interface copy, specifically labels for commands in buttons, menus, and other action-oriented interface elements. UI copy differs from microcopy or link text by representing actionable commands that change system state. The article covers best practices for command names and keyboard shortcuts, emphasizing clarity, consistency, and user efficiency while supporting accessibility and learning.

## Key Takeaways

- **Keep command text short while maintaining clarity** — Use one to four words maximum; avoid articles like "a" and "the" to improve scannability; include enough text to accurately describe the command.
- **Describe the consequent state, not current state** — Commands should reflect what state the system will move into rather than the current state; changeable labels help users understand subsequent states.
- **Lead with verbs for action commands** — Commands that initiate actions should begin with clear verbs or verb phrases like "Print" or "Accept and Sign In" to outline what happens.
- **Use adjectives for appearance-change commands** — When commands trigger changes in element appearance, use adjectives like "Bold" or "Italic" to describe how elements will change.
- **Avoid vague and branded terms** — Command names should be straightforward and descriptive, not cute or trendy; branded terms confuse users unfamiliar with application conventions.
- **Show keyboard shortcuts in menus** — Display associated keyboard shortcuts in tooltips, menus, and help sections to make shortcuts discoverable and memorable.

## Quotes

> Users want to be efficient with their time. Transparent command names and command shortcuts help users bridge the gulf of execution and are essential for a smooth, fast, and painless interaction.

> The application's name can be used as a label for the main application menu. And, while branded terms can add helpful context to menu items under the *Help* menu, in most cases, they should be avoided in command text.

> Help sections should also include printable images, cheat sheets, or lists of keyboard shortcuts that users can easily find and share.
