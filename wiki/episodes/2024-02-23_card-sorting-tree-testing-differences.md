# Card Sorting vs. Tree Testing

## Summary

Card sorting and tree testing are complementary but distinct UX research methods for addressing information architecture. Card sorting is a discovery method conducted early in design to generate ideas for content organization by observing how users naturally group items. Tree testing is an evaluative method used after an IA structure is proposed or exists, testing whether users can locate content within the hierarchy. Both methods can be conducted in-person or remotely using tools like OptimalSort (card sorting) or Treejack (tree testing). Understanding when to use each method—discovery vs. evaluation—ensures researchers extract maximum value from user research and make optimal IA decisions aligned with user expectations.

## Key Takeaways

- **Card sorting discovers mental models** — an early-stage discovery method revealing how users naturally categorize content without predefined structure.
- **Tree testing evaluates existing structures** — a later-stage evaluative method validating or comparing proposed hierarchies to ensure findability.
- **Limitations of card sorting** — results are suggestions, not prescriptions; individual variation requires designer judgment; only shows one categorization level.
- **Limitations of tree testing** — the isolated hierarchy lacks visual context (color, images, placement) that aids findability on fully designed sites.
- **Use both for comprehensive IA design** — combine discovery insights from card sorting with evaluative validation from tree testing to optimize navigation design.
- **Process differences reflect purpose** — card sorting uses individual labeled cards to explore groupings; tree testing uses text-based hierarchies to test navigation.

## Quotes

> Card sorting is used to determine how people categorize content, while tree testing evaluates an established navigation structure or can help compare alternative structures.

> Card sorting provides ideas for possible groupings. Often individual users will group the same content in different ways.

> One thing to consider when running a tree test is that users only see an isolated hierarchy which isn't a typical interaction when on a fully designed site.
