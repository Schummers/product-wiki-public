# Customization vs. Personalization in the User Experience

## Summary

Customization and personalization are often confused but are fundamentally different approaches to tailoring content and features for users. Personalization is done by the system, which identifies users and delivers content matching their role, whether at individual level (like Amazon's purchase-based suggestions) or group level (like intranet content filtered by job function). Customization is done by the user, who actively configures the interface to meet their specific needs. Both approaches have advantages and disadvantages: personalization offers a better experience without user effort but relies on the system's ability to guess correctly, while customization gives users control but requires their active participation. Neither should be used as a fix for a broken site; they should enhance already-good experiences and require careful consideration before implementation.

## Key Takeaways

- **Personalization is system-driven** — The system profiles the user and adjusts the interface automatically, either based on predefined roles or individualized models of each user.
- **Customization is user-driven** — Users actively make selections and set preferences to tailor the experience to their needs, giving them control but requiring their effort.
- **Personalization advantage** — Personalization provides improved user experience without requiring any extra effort from users; the system does the work automatically.
- **Customization advantage** — Customization allows users to get exactly what they want because they are in control; it respects user agency and preferences.
- **Don't use as a fix** — Neither customization nor personalization should be used as a solution for poor site structure or unclear content; they should enhance already-good baseline experiences.

## Quotes

> Personalization is done by the system being used. Developers set up the system to identify users and deliver to them the content, experience, or functionality that matches their role.

> Customization is done by the user. A system may enable users to customize or make changes to the experience to meet their specific needs by configuring layout, content, or system functionality.

> Personalization and customization should enhance an already good experience, rather than try to fix a poor one. They should be used thoughtfully, with a clear purpose.

## Concepts

- [[Personalization]] — Personalization uses system-driven intelligence to deliver tailored experiences automatically; successful personalization requires the system's model to match actual user needs.
- [[Customization]] — Customization empowers users to control their experience but requires user effort and initiative; not all users will engage with customization options.
- [[User Control]] — Customization supports user agency, while personalization trades control for convenience; different scenarios call for different approaches.
- [[Interaction Design]] — Both customization and personalization require thoughtful design to avoid adding complexity to the baseline experience.
- [[Information Architecture]] — Neither customization nor personalization can rescue poor information architecture; strong baseline structure must come first.
