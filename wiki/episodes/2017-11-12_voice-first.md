# Voice First: The Future of Interaction?

## Summary

Voice and screen interaction are converging from two directions: screen-first devices (phones, tablets) adding voice control, and voice-first devices (smart speakers) adding screens. Voice excels at efficient input and multitasking; screens excel at displaying information and reducing memory burden. Screen-first voice agents fragment functionality between voice and touch, create poor screen use, and omit visual affordances. Voice-first devices like Echo Show eliminate traditional GUI elements and build voice-inclusive screens, but this approach unnecessarily handicaps functionality. Long-term solutions need both modalities fully integrated without arbitrary handicapping.

## Key Takeaways

- **Complementary modalities** — voice is efficient input for hands-free operation and natural language; screens efficiently display large information sets and reduce cognitive load, making them natural complements.
- **Screen-first limitations** — voice agents on phones execute first step only, requiring screen input for continuation; voice-mode screens use awkward designs that waste space and omit affordances available in GUI.
- **Voice-only constraints** — smart speakers require remembering voice commands and audio sequences; lack of visual reference makes setting up complex tasks difficult.
- **Voice-first approach** — Echo Show primarily accepts voice input with screens re-introduced as integrated display; suggests sequential numbering for search results and ambient education for command discovery.
- **Limitation of pure voice-first** — arbitrarily prohibiting visual menus (e.g., no application list on 15,000+ skills) creates memory burden; combining both modalities without handicapping either is ultimately more effective.

## Quotes

> Voice is an efficient input modality: it allows users to give commands to the system quickly, on their own terms.

> A screen is an efficient output modality: it allows systems to display a large amount of information at the same time

> arbitrarily prohibiting visual menus for the sake of voice-first interaction would be like going into a fight with one hand tied behind your back
