# The Principle of Common Region: Containers Create Groupings

## Summary

The principle of common region is a Gestalt principle of visual perception stating that items within a boundary are perceived as a group and assumed to share common characteristics or functionality. In UX design, containers (borders, background colors, card layouts) help users quickly understand interface structure and determine which elements are related. Common region is a powerful visual cue that can override other grouping principles like proximity or similarity. However, overusing containers creates visual clutter and false floors that may prevent users from scrolling. The principle should be applied selectively, only when whitespace alone is insufficient to communicate groupings.

## Key Takeaways

- **Containers communicate relationships and structure** — Using borders or background colors to create common regions helps users understand which UI elements are related and connected. This is especially useful in complex interfaces with many options (print dialogs, navigation menus, filter panels).
- **Common region overpowers other grouping principles** — A boundary is a stronger visual cue than proximity or similarity. If elements are in a common region but spaced far apart, users will perceive them as grouped. Use this to resolve ambiguity when whitespace alone is insufficient.
- **Use common regions to separate chrome from content** — Background colors or borders for headers, footers, sidebars, and navigation areas effectively signal that these UI controls are separate from the main page content, helping users distinguish interface structure at a glance.
- **Cards and accordions leverage common regions** — Displaying labels within the same boundary as associated content visually connects them and establishes hierarchy. Tabs and accordions use common regions to group related options together.
- **Avoid overuse to prevent clutter** — Adding unnecessary borders and colored boxes creates visual complexity and false floors (stopping points that make users think they've reached the end of a page). Before adding borders, ask: are they necessary to understand grouping, or would whitespace suffice?
