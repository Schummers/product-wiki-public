# How to Maximize Insights in User Testing: Stepped User Tasks

## Summary

Stepped tasks are related tasks presented with progressively more specific instructions. The first step is vague, allowing researchers to observe whether users discover features naturally. Subsequent steps provide micro hints if users struggle with initial attempts. This approach captures insights about discoverability and findability that focused, directed tasks miss. Stepped tasks maintain the rhythm of usability testing as an observation exercise rather than conversation, preventing facilitators from helping too early and allowing for richer data collection from expensive test participants.

## Key Takeaways

- **Progressive specificity captures discoverability** — The first task should be broadest and vaguest. If users complete it without hints, you learn the feature is discoverable. If they struggle, subsequent stepped tasks provide micro hints to guide them, revealing discoverability and findability issues.

- **Avoid priming with UI terminology** — Do not use the same terminology in task instructions as appears in the UI. Using the same words primes users to search for that specific term, artificially improving task success and masking real discoverability problems.

- **Maintain test rhythm** — Handing users written stepped tasks reinforces that testing is observation, not conversation. This rhythm—task, user works, facilitator quiet, task ends, follow-up questions—is critical for authentic usability testing.

- **Pre-prepared beats ad-hoc questions** — Trying to invent new tasks during testing under time pressure leads to poor task design. Pre-writing stepped tasks ensures thoughtful, unbiased questions that help gather real information about UI usability.

- **Discoverability differs from usability** — Discoverability is whether users realize a feature exists. Findability is whether they can locate it when they know it exists. Usability is whether they can use it effectively. Stepped tasks reveal all three in sequence.

- **Every participant is expensive** — Since test participants are costly, stepped tasks extract maximum insight by revealing discoverability and findability problems that focused tasks miss entirely.

## Quotes

> When writing usability-testing tasks, you must walk the thin line between telling users too much and too little.

> Broad tasks give the users the opportunity to discover and access UI features by themselves, make the testing less directed or leading, and give you more insights about how the user naturally interacts with the UI. But, if users don't get to the feature of interest on their own, a stepped task can bring the user there so you can also learn about the feature's usability.

> Handing users a written task reinforces to them that the usability test is mostly an exercise in observation by the facilitator, not an interview or conversation.
