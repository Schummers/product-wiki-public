# User Control and Freedom (Usability Heuristic #3)

## Summary

This article explores the third usability heuristic: user control and freedom. The principle states that users should be able to escape unwanted states and undo mistakes through clearly marked emergency exits. The article examines how to support user control through back links, cancel options, close actions, and undo functionality, and discusses common design mistakes that make users feel trapped rather than in control.

## Key Takeaways

- **Always allow going back** — Users should be able to return to previous screens or states; never disable the browser Back button or prevent users from leaving your site, as this frustrates users and damages business goals.
- **Meet back button expectations** — The browser Back button should return users one step backward; overlays should not cause back navigation to exit the site entirely, and apps should meet users' mental models of back navigation.
- **Make exits discoverable** — Close, exit, and cancel links should be positioned where users expect them (top right for overlays) and accompanied by text labels or universal icons so users can find them when needed.
- **Support undo easily** — Users should be able to undo changes at multiple levels; undo can be implemented as explicit buttons, contextual snackbars, toggles, or remove links depending on context.
- **Ensure undo discoverability** — Don't rely solely on keyboard shortcuts for undo; provide visible UI options in expected locations (toolbars, menus) and show keyboard shortcuts alongside UI controls to support learning.

## Quotes

> **Users should be able to quickly correct mistakes or backtrack on choices made**. The ability to easily get out of trouble encourages exploration, which facilitates learning and discovery of features.

> **Never stop users from leaving your site by disabling the browser Back button.** Some sites deliberately make their site sticky, preventing users from returning to the search engine.

> To ensure users have a sense of freedom and control using your product, they should be able to easily abandon a task, go back a step, and undo a change they've made to the system's state.

## Concepts

- [[User Control]] — empowering users to navigate interfaces, abandon tasks, and recover from mistakes through clear exit points, back navigation, and cancel options.
- [[Undo and Redo]] — supporting users in reversing mistakes and exploring interface possibilities by providing multiple undo mechanisms and ensuring undo is discoverable and available at multiple levels.
- [[Navigation Design]] — designing back links, overlays, and multi-step processes so that back navigation works predictably and meets users' mental models of how navigation should function.
