# Polyhierarchies Improve Findability for Ambiguous IA Categories

## Summary

A polyhierarchy is an information architecture structure where child nodes have multiple parent categories. Unlike traditional tree hierarchies where each item has one location, polyhierarchies allow items to appear in multiple places to support different user mental models. This is particularly valuable for ecommerce where products naturally fit multiple categories. However, polyhierarchies should be used restrained; excessive use clutters navigation menus and increases cognitive load. Polyhierarchies conflict with breadcrumb navigation since a canonical path must be chosen, creating a trade-off.

## Key Takeaways

- **Multiple mental models support** — polyhierarchies accommodate the fact that different users naturally categorize the same item differently; placing products in multiple locations prevents users from assuming the site doesn't carry items not in their expected location.
- **Digital affordance** — while physical objects can exist in only one location, digital items easily appear in multiple hierarchical paths, making polyhierarchies practical on websites without physical constraints.
- **Restraint requirement** — excessive polyhierarchies bloat navigation menus and increase cognitive load; items should appear in only the two or three most natural parent categories based on user research, not every possible location.
- **User research foundation** — card sorting and tree testing reveal where users expect to find items; polyhierarchies should reflect these mental-model differences, not be added speculatively.
- **Breadcrumb trade-off** — polyhierarchies conflict with breadcrumb navigation since only one canonical path can be shown; designers must choose between breadcrumbs and comprehensive polyhierarchy support.

## Quotes

> A polyhierarchy refers to a graph structure in which at least some child nodes have more than one parent nodes.

> Polyhierarchies pose a big difficulty for physical objects: if you only have one copy of a book (or only one piano), it can only be in one place. To avoid polychierarchies, many complicated ways of classifying items emerged; they involve carefully structured taxonomies and judicious use of crossreferencing (such as the Library of Congress's classification system, for example).

> Users frequently assume that, if a product is not present in the place where it "ought" to be, the site doesn't carry that product.
