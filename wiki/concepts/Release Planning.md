## Sources (5)

- [[2014-09-05_user-story-mapping_07-2-plan-to-build-less]] — Patton describes slicing a story map horizontally to create a release roadmap where each slice targets specific outcomes, allowing incremental delivery of large systems while showing benefit with each release.
- [[2014-09-05_user-story-mapping_08-3-plan-to-learn-faster]] — The story map organizes releases as slices, with the top slice being current work, and lower slices representing future releases; each release has explicit learning goals.
- [[2014-09-05_user-story-mapping_09-4-plan-to-finish-on-time]] — Involves creating a development plan that slices the work into opening game (technical foundations), midgame (feature completion), and endgame (refinement); teams estimate and manage this plan as a budget.
- [[2014-09-05_user-story-mapping_16-11-rock-breaking]] — The chapter outlines the full journey from opportunity to release: opportunity discussions filter ideas, discovery identifies a minimum viable solution, story workshops prepare for delivery, teams build with ongoing conversation, and evaluation at multiple stages (internal quality, user feedback, stakeholder visibility, post-release metrics) informs the next cycle.
- [[2014-09-05_user-story-mapping_23-18-learn-from-everything-you-build]] — Release readiness can be evaluated using a report-card approach: for each major user activity, ask "If we shipped now, what grade?" and focus remaining time on the lowest-graded areas. Time constraints often matter more than perfect completeness.
