# Interaction and Interface Patterns

## When to open this theme

Choosing a control, designing a form, a modal, an error, a notification, or any concrete interface component.

Component-level guidance and the patterns behind it. For whether the component is usable at all, go to [[Usability Heuristics and Evaluation]].

## Concepts (12)

- [[Interaction Design]] (64 sources) : the widest component theme: feedback, mappings, motor constraints, modes, gestures, ethics
- [[Design Patterns]] (31 sources) : deciding whether a pattern applies to you, plus controls, menus, disclosure and icons
- [[User Interface]] (26 sources) : making objects and actions visible, choosing controls, dialogs and modes, evaluating the result
- [[Form Design]] (17 sources) : asking for less, layout and sequencing, labels, validation, buttons, multi-step flows
- [[Progressive Disclosure]] (11 sources) : breaking long tasks into steps, layering depth, and signalling that more exists
- [[Feedback Design]] (10 sources) : confirming the action registered fast, choosing the mechanism, encoding status redundantly
- [[Error Prevention]] (8 sources) : designing for the inattentive user, confirmation dialogs used sparingly, defence in depth
- [[Error Messages]] (8 sources) : placement, wording, the inline-validation timing tension, and recovery
- [[Animation]] (6 sources) : using motion for a purpose, timing, scroll-triggered motion, and motion sensitivity
- [[Modal Window]] (5 sources) : questioning the pattern first, legitimate cases, timing, and why cancel is not close
- [[Notification Design]] (5 sources) : classifying before designing, timing, intensity and fatigue, permission and the ethical line
- [[Affordance]] (5 sources) : the learning cost of invisible interactions, icons as signifiers, signalling current state
