# SCHEMA — the writing contract for this vault

Every agent writing into `wiki/` follows this file. It defines the templates,
the frontmatter, and the rules. Read `CONTEXT.md` first for what the words mean.

Language: **English** for everything new, and for every concept page without
exception (`docs/adr/0002-anglais-langue-du-corpus.md`). Legacy Parlons Design
records stay in French; do not translate them opportunistically.

---

## Folders

- `raw/sources/` — verbatim material, written by the fetch scripts. **Never
  edited, never deleted.** Read-only for every agent.
- `wiki/episodes/` — one record per source.
- `wiki/concepts/` — cross-source concept pages.
- `wiki/themes/` — the routing layer: one page per theme, plus `_router.md`.
  Generated by `stage3/generate_themes.py`. Never hand-edited.
- `wiki/orphans.md` — generated index of single-source concepts that have no
  page. Never hand-edited.
- `wiki/index.md` — generated by `generate_index_and_concepts.py`. Never
  hand-edited. A flat 220 KB catalogue: useful to a human scanning the corpus,
  useless for routing. Agents read `wiki/themes/_router.md` instead.
- `wiki/log.md` — ingestion journal.

File naming:

- Record: `wiki/episodes/<YYYY-MM-DD>_<slug>.md`, date = publication date, so
  alphabetical order is chronological order.
- Book chapter (raw and record share the basename):
  `<published>_<book-slug>_<NN>-<chapter-slug>.md`. A book is N raw files and
  N records, one per chapter, flat in the same folders (`docs/adr/0005`).
- Concept: `wiki/concepts/<Concept Name>.md`, Title Case, matching `name`
  exactly (the wikilink target is the filename).

## Record template (`wiki/episodes/`)

```markdown
---
type: source
name: Readable Title Of The Source
created: YYYY-MM-DD
published: YYYY-MM-DD
source_type: video
status: summarized
url: https://...
author: Romain Penchenat
raw: raw/sources/<file>.md
concepts:
  - Concept One
  - Concept Two
---

# Readable Title Of The Source

## Summary

One or two paragraphs: what this source is about and the context it sits in.

## Key Takeaways

- **Takeaway** — what the source actually says about it, in enough detail to be
  useful without reopening the raw file.

## Quotes

> A verbatim quote, in the source's original language.

## Concepts

- [[Concept One]] — what this specific source contributes to that concept.
- [[Concept Two]] — same.
```

Field rules:

- `type` — always `source`.
- `name` — human-readable title, no date prefix.
- `created` — the day the record was written. `published` — the day the
  publisher released it. They are different fields; never collapse them.
- `source_type` — `video` | `article` | `book` | `paper` | `transcript` |
  `document` | `repo` | `other`.
- `status` — `raw` | `summarized` | `processed`. `summarized` once the record is
  written; `processed` once the concept stage has folded its concepts in.
- `raw` — repo-relative path to the verbatim file. Required.
- `book`, `chapter` — present on a chapter record only (`source_type: book`),
  copied from the raw file. `name` reads `<Book>: <Chapter>`, `published` is
  the book's date, `url` its reference page, `author` the book's authors even
  for a guest-written chapter. The raw file also carries `book_slug`, `part`,
  `chapter_number` and `extraction` (how the text was produced).
- `concepts` — flat list of **plain strings, not wikilinks**. This is the
  machine-readable field the generator reads. Names here are *candidates*: the
  record stage proposes, the concept stage decides. The `## Concepts` section
  below carries the same names as wikilinks, with the per-source detail.

## Concept template (`wiki/concepts/`)

```markdown
---
type: concept
name: Concept Name
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: stub
aliases:
  - Ancien Nom Français
  - Concept Names
---

# Concept Name

## Definition

A general synthesis of the concept as the sources describe it.

## Practice

Structured compilation of the guidance the sources give. Sub-headings when it
helps. Attributed: when two sources disagree, say so rather than picking one.

## Sources

- [[YYYY-MM-DD_slug]] — what this source says specifically about this concept.
```

Field rules:

- `status` — `stub` (1–2 sources) | `developed` (enough for real cross-source
  reading, eligible for synthesis) | `synthesized` (a synthesis exists).
  `developed` requires 5+ records **and 2+ distinct works**: a work is a book
  when the record has one, the record itself otherwise. Eight chapters of one
  book are eight records but one work, and stay `stub` (`docs/adr/0005`).
- `aliases` — every name this concept must not be duplicated under: French
  legacy name, English variant, plural, acronym. Adding an alias is cheap;
  a duplicate is expensive.
- `updated` — bumped whenever a source is folded in.

A `synthesized` concept gains a `## Synthesis` section. Its shape is
deliberately unspecified until the first one is written.

## Theme template (`wiki/themes/`)

A theme is the routing layer above the concepts: it groups them so an agent can
go from a question to the two or three pages worth opening, without loading the
catalogue. Fully generated — the curation lives in `stage3/theme_map.py` and the
judgement in `stage3/theme_prose.py`. Editing a generated file loses the edit on
the next run.

```markdown
---
type: theme
name: Theme Name
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: active
concepts:
  - Rank One Concept
---

# Theme Name

## When to open this theme

Trigger list on the first line, under 160 characters: it is what `_router.md`
prints. Nuance below it.

## Concepts (N)

- [[Concept]] (N sources) : what opening that page buys you.

## Sharp edges (N)

- [[Stub Concept]] : [[record]], [[record]]
- **Unlinkable Concept** : [[record]]
```

Field rules:

- `name` — English, ASCII, and **never equal to a concept name or alias**.
  `verify_wiki.py` enforces it: a collision would make a wikilink ambiguous.
- `concepts` — rank-1 `developed` concepts, sorted by source count. A concept
  may sit in several themes; every `developed` concept sits in at least one.
- **Sharp edges** are rank 2: stubs and single-source names, derived from shared
  records, not curated. Bold means no page exists — open the record.

`_router.md` (`type: theme-router`) is the entry point: the first file an agent
reads, and the only one it needs in context to choose where to go next.

## The four stages

Who may write what. Violating this is what produces duplicates.

| Stage | Writes | Model |
|---|---|---|
| 0 Scrape | `raw/sources/` | none, pure script |
| 1 Records | `wiki/episodes/` | cheap, parallel |
| 2 Concepts | `wiki/concepts/`, `wiki/index.md`, `wiki/log.md` (incremental: `stage2/fold_records.py`) | strong |
| 3 Themes | `stage3/theme_prose.py` -> `wiki/themes/` | strong |
| 4 Playbooks | `wiki/playbooks/` | strong, on demand |

Stage 3 writes the routing layer. Stage 4 distils a theme into checkable rules
for a design review, and runs only on the themes a review actually uses
(`stage3/theme_map.PLAYBOOK_THEMES`, `docs/adr/0004`).

**Stage 1 must never create or edit a concept page.** It proposes candidate
names in `concepts:` and writes the `## Concepts` wikilinks. Broken links are
expected and fine at that point — stage 2 resolves them.

---

## Rules

1. **No fabrication.** A record contains only what its source says. No advice,
   no example, no nuance the source didn't provide. The vault is a faithful
   reflection of the corpus, not a commentary on it.
2. **Attribution never disappears.** Nothing in this vault is the owner's own
   thinking. Personal notes belong in `../second-brain/knowledge/notes/`.
3. **Anti-duplicate, before creating any concept**: search existing concept
   filenames **and** every `aliases` entry (`rg -i` over `wiki/concepts/`). If a
   near match exists, enrich it and add the new wording as an alias. Create only
   when nothing matches. Singular over plural, established term over coinage.
4. **Bidirectional links.** A record links to its concepts; each of those
   concepts lists that record under `## Sources`. Stage 2 owns the return link.
   `verify_wiki.py` checks it.
5. **Wikilinks** (`[[Name]]`) for anything inside this vault, Markdown links for
   external URLs. Wikilinks never cross into the second brain.
6. **ISO dates** everywhere, `YYYY-MM-DD`.
7. **Quotes stay in their original language**, even in an English record.
